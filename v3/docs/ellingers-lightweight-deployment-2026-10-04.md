# Ellingers lightweight watchdog deployment — 4 October 2026

The gateway's V3 watchdog now serves the cream and teal dashboard at `/` and `/lite`. The main page shows five essential health cards, the last restart, recent significant events, and a collapsed diagnostics panel. `Download evidence` creates a bounded ZIP from saved state, recent logs, current blackbox segments and the latest incident archive. The web process only reads saved data and does not offer recovery, commissioning, or purge actions.

V3 remains the only software recovery owner. The independent Neousys hardware feeder, 2-second rolling blackbox recorder, boot attribution, heartbeat, incident archives, service/process checks, connectivity, and actual recording storage checks remain enabled. The disabled people-counting collector no longer starts a thread in lightweight mode. Generic disk enumeration and the legacy website are absent from the running interface.

Routine history is compact, sampled every 60 seconds, and capped at 20,000 rows over 30 days. Healthy rows older than 48 hours are thinned to one per five-minute interval; fault rows retain minute resolution. History appends now read a bounded tail instead of the full file. Event reads are bounded, and the live event file rotates at 4 MiB. Routine router-cell notices are retained in the event log but omitted from the main page timeline. General retention can trim routine history/events, but it cannot delete reboot attribution, recovery control state, heartbeat, current blackbox segments or incident archives.

Collector intervals on this gateway: hardware 10s, services 15s, storage 60s, network 30s, router 60s, process 15s, retention 300s. The main poll and heartbeat remain at 5s. The hardware feed remains at 10s with a 30s timeout. The blackbox remains at 2s with a 15-minute rolling window and 10s checkpoints.

The retired watchdog code, state, and 559,538,969 bytes of duplicate logs were archived with SHA-256 verification before their old directories were removed. The compressed archive is 23,266,992 bytes at `/var/backups/va-watchdog/lightweight-20261004/legacy-retired.tar.gz`; hashes are in `legacy-manifest.json`. That backup directory also contains original and staged V3 code, the original and staged configuration, and verified compressed copies of the predeployment V3 history and events. Existing incident archives remain under `/var/lib/va-watchdog/incidents`.

After deployment, history fell from 73,387,759 to 12,844,511 bytes and the active events file was bounded to about 4 MiB. The root page, health API, lite API, and evidence ZIP all returned HTTP 200. The V3 monitor, web server, and hardware feeder were active, the boot ID was unchanged, recovery was idle under V3, the feed had zero errors, and current checks had no critical results. The live browser rendered Ellingers as healthy, with the last restart attributed to the earlier network-loss reboot. This confirms normal running after deployment; it does not simulate a real freeze or reboot.

The lightweight web mode is enabled by `web.lightweight: true` in `/etc/va-watchdog/config.json` on Ellingers. The old V3 web module remains in the code tree for rollback but is not imported or exposed by the running web service. The Ellingers gateway is Ubuntu 22.04.5 LTS.
